## [0.3.3] - 2026-11-03
### Changed
- The AI usage log is no longer in this repository: it is submitted as its own deliverable (folder "AI logs Hillpointe
  assessment"), with its links into the code pointing at the public GitHub repo. `scripts/export_ai_log.py` now takes the
  output folder as an argument.
- One-page summary: "What I would build next" (a same-building cost check on every invoice; a plain-language pre-check for
  subcontractors) and how the governance context (`AGENTS.md` + `governance/`) supports future development.
- AI usage log restructured for submission: `governance/ai-usage-log/README.md` (report: two uses of AI, how it was
  directed, defect register, human decisions, security, cost, NIST AI RMF mapping, what to do differently),
  `sessions/S01–S11` on one template, and a prompt ledger + condensed transcript **generated** from the session record by
  `scripts/export_ai_log.py` with automatic redaction and a leak check. The previous hand-written notes are replaced
  (they quoted only half the prompts). Added `ENGINEERING_RECORD.md` (planning, research, architecture, evaluation and
  prompt engineering behind the work) and `DIRECTION_LOG.md` (each instruction as a structured brief).
### Fixed
- UI cost estimate used Opus 5 prices ($5/$25 per million tokens) instead of Opus 5.5 ($4/$20, cache reads $0.20); every
  cost figure in the docs recomputed from the token metering ($2.38 for all 84 readings, $0.028 each; drill run $0.81).

## [0.3.2] - 2026-11-02 (pre-interview audit)
### Fixed
- `ap diff` and the UI's **Preview impact** now also report changes that don't flip a decision: terms, due/posting dates,
  doc type, coding lines, Entrata post month/due date/approver, and the route. Before, a change such as vendor terms or
  "force open period" showed "0 changed". Decision records now store the bill header and route.
- A damaged Word file no longer stops the run (held like a damaged PDF).
- "More than one invoice in a file" only counts invoice-number headers (line starts, must contain a digit), and ignores
  the original a credit or revision names. Credits, revisions and "please reference invoice number" footers are not held.
- Price-variance help text named the wrong route (it holds as OTHER → AP Manager).
### Added
- `ap run` takes a `.zip` (unpacked next to it) and reads sub-folders; an empty folder stops with a clear message.
- Reports and `run_meta.json` show the inbox relative to the project (no local home path). Evidence runs regenerated:
  identical decisions, lines and totals; only the run ids changed.
### Changed
- Terminal summary is listed by file name. ADRs in order. Traceability matrix cites real tests (verified against
  `pytest --collect-only`). SUMMARY, runbook, tech stack and rerun evidence docs brought up to date.
- Only the canonical ledger snapshots (`submitted`, `pre-01…`, `pre-07…`) are committed.
- Source repository made public (history checked for keys first: none).
- The ledger stores inbox folders relative to the project, so a clone, a downloaded zip and the public demo are
  identical. Evidence regenerated again (same outputs; new run ids).

## [0.3.1] - 2026-11-02
### Added
- UI Import takes a whole folder (picker or drag-and-drop, sub-folders included) or `.zip` archives, not only single files.
  Everything is flattened into one inbox; clashing names get a suffix; hidden/OS junk and `../` zip entries are dropped.
  Non-PDF/image/Word files are flagged before upload (the engine holds them as unreadable, never guessed).
- Delete a run (ADR-0013): UI (run page **Delete**, trash icon on Home cards) and `ap delete-run <id>`. Latest recorded run
  or any preview only; impact shown first; typed `DELETE` confirmation; ledger snapshot, archived output and audit log.
- Interview drill pack `tests/synthetic/interview_drill.zip` (33 blind documents of every kind, generated by
  `tests/synthetic/generate_drill.py`), answer key `tests/synthetic/INTERVIEW_DRILL_ANSWER_KEY.md`, `tests/test_interview_drill.py`.
  Live run with Claude: 33/33 in 39 s, $0.81.
- Hold OTHER when one file holds more than one invoice (A-24). WARN on bills dated in a future period (A-23).
- Damaged PDFs are recognised at intake, held with "ask the vendor to resend", never sent to the model (A-25).
- Public read-only demo on GitHub Pages (https://devansh-codes.github.io/hillpointe-ap-demo/), built by
  `scripts/build_site.py` / `make site` from the submitted state. Published from a separate public repo that holds only the
  built site; this source repo stays private. Local paths scrubbed; no keys, `.env` or extraction cache included.
### Changed
- UI: confidence is no longer shown as High/Medium/Low. Only documents the AI was unsure of carry a "Check reading" tag.
- Clearer message for non-bill documents such as W-9s, quotes and insurance certificates.
### Fixed
- Home cards: long file names no longer overlap the amount.
### Removed
- "System ready" indicator from the sidebar (the system check stays in the top bar).

## [0.1.0] - 2026-11-02
### Added
- Hybrid pipeline: Claude Opus 5.5 extraction (`messages.parse` + Pydantic schema, PDF/image/DOCX) → deterministic rules → coding → Field Guide validator → outputs → SQLite ledger.
- 16 policy rules (`src/ap_automation/rules/core.py`), all driven by `config/policy.yaml`.
- Outputs: Intacct CSV + XLSX on the provided template, Entrata handoff, exception log, approvals, run report (MD/HTML), decision trace (JSONL).
- Ledger with UNIQUE(vendor, normalised bill no), snapshots, what-if runs, CSV register.
- CLI: `run`, `doctor`, `explain`, `diff`, `snapshot save|restore|list`, `policy validate`, `reset-state`, `eval-extraction`.
- Hand-labelled ground truth for all 32 package documents; synthetic hold-out generator (24 scenarios, 2 layouts, PNG, DOCX).
- 92 tests; Makefile (`test`, `evidence`, `demo`, `eval`), `run.sh`, README for the AP team.
### Changed
- Plan deviations C-1 to C-10 recorded in `PLAN.md` §11 (notably: no temperature parameter; A-13 → NOPO).
### Fixed
- YAML reads bare `NO` as boolean: quoted, plus a validator guard.
- Run ids now unique to the millisecond.
- A resent bill is no longer counted against its own PO balance.
