## How the AI was directed / what it did

1. Checked the environment before building: uv 0.13, Python 3.12, **no API key**. Decided to build behind an extractor interface with hand-labelled fixtures, not to block on the key.
2. Read the bundled Claude API docs before writing extractor code (exact `messages.parse` signature, PDF block shape, effort parameter). Found that `temperature` is removed for Opus 5.5 / API 2026-10-21, and recorded that as a plan change (C-1) instead of silently dropping it.
3. Built the modules in plan order: models/config → loaders → extraction + quality controls → resolver → 16 rules → coding → validator → engine → ledger → emitters → CLI.
4. Transcribed all 32 package documents into labels (`tests/fixtures/build_labels.py`) from the PDF text.
5. First end-to-end run found a real bug (YAML `NO` → boolean); fixed it and added a validator guard.
6. Golden tests found a wrong test constant (the code was right) and a run-id collision (fixed).
7. Generated a 24-scenario synthetic hold-out set rendered from labels (2 PDF layouts, PNG scan, DOCX, unsupported file). It found one presentation issue (a resend reported as DUP + OVERPO), fixed by excluding a bill from its own PO balance.
8. Dress-rehearsed the live session through the real CLI: run → rule change → restore → rerun → diff → explain.
